# テスト鯖でのメッセージの確認（preview）

Bot の主な返信を、テスト鯖のチャンネルで実際に読むための手順です。本番の Discord には影響しません。投稿するのは、モジュールの `showcase_` で始まるテスト（モデレーション、ログ、自動モデレーション、ping）が出したメッセージだけです。ショーケースは日本語で動きます。

## 手順

1. 記録付きでテストを実行します。`CLOSURE_DUMP_DIR` を設定したときだけ、テストが実行した Action が `<dir>/<プロセス ID>.jsonl` に 1 行 1 件の JSON として追記されます。各行には、その Action を出したテストの名前（`test`）も入ります。設定が無いときは何も書かれません。

   ```
   CLOSURE_DUMP_DIR=<dir> cargo test --workspace
   ```

2. 前回の投稿を消します。この Bot が投稿したメッセージのうち、`--after`（Unix 時刻・秒）以降のものだけを消します。それより前のものは残ります。

   ```
   cargo run -p closure-xtask -- clear --channel <チャンネル ID> --after <Unix 時刻>
   ```

3. 記録されたメッセージを投稿します。トークンは `DISCORD_TOKEN` から読みます。環境変数に無ければ、カレントディレクトリ（上位を含む）の `.env` から読みます（本体と同じ方法）。トークンの値は表示も記録もされません。

   ```
   DISCORD_TOKEN=<テスト用 Bot のトークン> cargo run -p closure-xtask -- replay --dir <dir> --channel <チャンネル ID>
   ```

   投稿先は `--channel` で指定したチャンネルだけです。テスト用 Bot のトークンを使ってください。

## 投稿する内容

- 投稿するもの: テスト名の最後の部分が `showcase_` で始まるテストが出した、メッセージ、埋め込み付きの応答、DM。テスト名は付けません。
- DM（`SendDirectMessage`）は、先頭に `DM to <ユーザー ID>` の行を付けて、同じチャンネルに埋め込みのまま投稿します。
- 投稿しないもの（件数だけを最後に 1 行で表示します）:
  - `showcase_` で始まらないテストの出力
  - ロールの付与や削除、BAN、タイムアウト、メッセージの削除など、本文を持たない操作
  - 応答の `defer`、`modal`、`autocomplete` など、本文を持たないもの
  - 本文も埋め込みも無いメッセージ
  - 本文が 15 文字未満のメッセージ
  - テストの固定のユーザー ID（`<@7>`、`<@9999>`、`(7)`、`(9999)`）を含むメッセージ
  - 同じ種類のメッセージ（本文の先頭 25 文字が同じもの。数字は `#` に置き換えて比べます）は 1 回だけ投稿します

その他の注意:

- ボタンやセレクトメニュー（components）は送りません。
- メンションは通知されないように送ります。
- 投稿に失敗したメッセージは表示し、終了コードを失敗にします。

## ショーケースの追加

ショーケースは日本語のサーバーとして動きます（`set_guild_locale(Locale::Ja)`）。見せたい返信は、`showcase_` で始まるテストとして書きます。現実的な名前、理由、ID を使い、ハーネスでコマンドを実行して返信を確かめます。テストの名前がそのまま記録の `test` になります。

## 注意

- ショーケースに無い場面は出ません。テストが通った経路だけが記録されます。
- `closure-core` の `MockApi` を通らない経路は記録されません。
- 同じ `<dir>` に古い `.jsonl` が残っていると、それも投稿されます。新しいディレクトリを使ってください。
- ファイルの順序は、ファイル名（プロセス ID）の順です。テストの実行順とは一致しません。
- Discord の上限（本文 2000 文字、埋め込み 10 個など）を超えるメッセージは、Discord が拒否し、失敗として表示されます。
