# テスト鯖でのメッセージの確認（preview）

テストで Bot が出すメッセージ（本文、埋め込み、DM）を、テスト鯖のチャンネルで実際に読むための手順です。本番の Discord には影響しません。

## 手順

1. 記録付きでテストを実行します。`CLOSURE_DUMP_DIR` を設定したときだけ、テストが実行した Action が `<dir>/<プロセス ID>.jsonl` に 1 行 1 件の JSON として追記されます。設定が無いときは何も書かれません。

   ```
   CLOSURE_DUMP_DIR=<dir> cargo test --workspace
   ```

2. 記録されたメッセージをテスト鯖のチャンネルに投稿します。トークンは `DISCORD_TOKEN` から読みます。環境変数に無ければ、カレントディレクトリ（上位を含む）の `.env` から読みます（本体と同じ方法）。トークンの値は表示も記録もされません。

   ```
   DISCORD_TOKEN=<テスト用 Bot のトークン> cargo run -p closure-xtask -- replay --dir <dir> --channel <チャンネル ID>
   ```

   投稿の前に、件数だけを確認できます（送信しません。トークンも要りません）。

   ```
   cargo run -p closure-xtask -- replay --dir <dir> --channel <チャンネル ID> --dry-run
   ```

   投稿先は `--channel` で指定したチャンネルだけです。テスト鯖のチャンネル ID を指定し、テスト用 Bot のトークンを使ってください。

## 変換の規則

投稿するもの（すべて `--channel` のチャンネルへの通常のメッセージになります）:

- `SendMessage`、`SendFile`（本文と埋め込みだけ。添付ファイルは送りません）
- `SendDirectMessage`（先頭に `DM to <ユーザー ID>` の行を付けます。DM は別の場所に届かず、同じチャンネルに投稿されます）
- `Respond`（メッセージと変更の応答のみ）、`Followup`、`EditResponse`（いずれも新しいメッセージとして投稿します）

投稿しないもの（種類ごとの件数を最後に表示します）:

- ロールの付与や削除、BAN、タイムアウト、メッセージの削除など、本文を持たない操作
- 応答の `defer`、`modal`、`autocomplete` など、本文を持たないもの
- 本文も埋め込みも無いメッセージ

その他の注意:

- ボタンやセレクトメニュー（components）は送りません。
- メンションは通知されないように送ります。
- 似た内容は 1 回だけ投稿します。数字だけが違うもの（ID や件数の違い）は同じ内容とみなします。例: 「件数 3」と「件数 5」は 1 回だけ。
- 投稿に失敗したメッセージは表示し、終了コードを失敗にします。

## 注意

- テストに無い場面は出ません。テストが通った経路だけが記録されます。
- `closure-core` の `MockApi` を通らない経路は記録されません。
- 同じ `<dir>` に古い `.jsonl` が残っていると、それも投稿されます。新しいディレクトリを使うか、実行前に古いファイルを消してください。
- ファイルの順序は、ファイル名（プロセス ID）の順です。テストの実行順とは一致しません。
- Discord の上限（本文 2000 文字、埋め込み 10 個など）を超えるメッセージは、Discord が拒否し、失敗として表示されます。
